# Metrics Summary

Every number below is generated by `notebooks/analysis.ipynb`. Phishing = 1, Safe = 0. Precision, recall and F1 refer to the phishing class.

## Dataset and cleaning
- **18,650 raw rows**: emails in the original Kaggle file.
- **16 null emails removed**: rows with no email text.
- **536 blank/placeholder emails removed**: text that was empty or just the word "empty" (which appeared under both labels).
- **563 duplicates removed**: exact repeats, removed before splitting so no email can appear in both training and test data.
- **1 corrupted record removed**: a 17-million-character row containing ~5,200 merged emails and a notebook file under one "Safe" label.
- **17,534 clean emails (6,556 phishing / 10,978 safe, 37.4% phishing)**: the dataset used for all analysis.
- **14,027 train / 3,507 test emails**: one stratified 80/20 split (random_state=42), shared by every model.

## Checklist measurements (phishing vs. safe)
- **Urgency phrases in 29.4% vs. 10.3%** of emails: phishing uses urgency language about 2.9x as often, but most phishing has none.
- **Exclamation marks in 60.4% vs. 22.3%** (average 3.43 vs. 0.63 per email): the clearest single difference between the classes.
- **Sensitive-info bait phrases in 10.5% vs. 4.3%**: more common in phishing, but rare in both.
- **IP-address links in 2.41% vs. 0.05%**: a strong signal when present, but present in very few phishing emails.
- **Links in 37.9% vs. 41.7%**: safe emails contain links slightly more often, so link presence alone does not indicate phishing here.
- **Median length 764 vs. 1,021 characters**: phishing emails tend to be shorter.

## Evasive phishing (no urgency phrases, no links, no IP links)
- **2,915 of 6,556 phishing emails (44.5%)**: share of all phishing that has none of these classic red flags (SQL query 3).
- **574 of 1,311 test-set phishing emails (43.8%)**: the same share within the test set.
- **A: Handcrafted features + Random Forest caught 304 of 574 (53.0%)**: the checklist model still catches about half because its six measurements include exclamation marks and length, which are not part of the "no warning signs" definition.
- **B: TF-IDF + Logistic Regression caught 549 of 574 (95.6%)**: the text model before removing source fingerprints recognizes these emails from their wording.
- **B2: TF-IDF + LR, artifacts removed caught 536 of 574 (93.4%)**: the text model; the result holds after removing source fingerprints.

## SQL risk ranking
- **328 emails in the top 5% risk group**: phishing ranked by urgency_score then bait_score using NTILE(20); minimum urgency_score in the group is 2.

## Model results (test set, 3,507 emails)

### Model A: checklist model (Random Forest on the six checklist measurements)
- **Precision 0.653**: when the model flags an email as phishing, it is right 65.3% of the time.
- **Recall 0.638**: it catches 63.8% of the phishing emails in the test set.
- **F1 0.645**: the balance of precision and recall (1.0 = perfect).
- **5-fold CV F1 0.633 ± 0.022**: average F1 across five training-set slices, and how much it varies; a small ± means the score is stable.
- **Accuracy 0.738**: share of all test emails classified correctly (reported for completeness; 62.6% would be scored by always guessing "Safe").
- **836 caught / 475 missed phishing; 445 false alarms / 1,751 correctly passed safe emails**: the confusion matrix on 3,507 test emails.

- **5-fold CV F1 0.971 ± 0.003**: average F1 across five training-set slices, and how much it varies; a small ± means the score is stable.

## Corpus artifact check (Model B)
- **9 of the top 20 "safe" terms and 3 of the top 20 "phishing" terms are source fingerprints** (e.g. "enron", staff names, years, phone area code 713): the model partly learned which dataset an email came from.
- **"enron" appears in 2,239 safe emails and 1 phishing**: example of a token that identifies the source, not the intent.
- **F1 0.975 → 0.965 after removing artifacts** (missed phishing 40 → 66): artifact tokens account for only a small part of the score.
- **After removal, 0 listed artifacts remain in the top 20 safe terms, but header/formatting words ("date", "pm", "cc", "forwarded") and source topics ("linguistics", "university", "linux") still rank highly**: scores reflect separating these specific corpora, so real-world performance on modern email would likely be lower.
